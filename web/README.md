# Матчасть — демо-интерфейс

Интерфейс в духе NotebookLM над конвейером `rag_textbook`: источники, чат с
ответом по фрагментам, просмотр документа и живая сцена поиска («Как я ищу») —
понятия из вопроса, обход графа, кандидаты по тексту и через граф,
переранжирование и отбор фрагментов в контекст.

## Состав

- `src/` — фронтенд (Vite + React). Две реализации API с одним интерфейсом:
  заглушка (`npm run dev`) и HTTP к демо-сервису (`npm run dev:api`, сборка).
- `server/demo_api.py` — демо-сервис на FastAPI. Пайплайн не меняет: строит
  `RetrievalPipeline` на каждый запрос, оборачивает его стадии и хранилище графа
  и отдаёт шаги потоком SSE (`/api/ask`). Код конвейера берёт из репозитория,
  указанного в `--repo` (по умолчанию — этот же репозиторий).
- `server/titles.json` — человеческие названия книг вместо идентификаторов.

Загрузка новых документов на стенде выключена: разбор книги идёт часами,
поэтому библиотека индексируется заранее.

## Локально, без сервера

Граф из файла, BM25 вместо векторов, без модели ответа (вместо ответа —
выписка из найденного). Сцена поиска при этом настоящая.

```bash
.venv/Scripts/python.exe web/server/run.py --offline artifacts/graphs/v4.json.gz
```

```bash
npm run dev:api --prefix web
```

Открыть http://localhost:5173. Без сервиса, на заглушке: `npm run dev --prefix web`.

## На арендованном сервере

1. Локально: `npm run build --prefix web`, затем один архив с `web/server` и `web/dist`.
2. На сервере распаковать в корень репозитория; `.env` репозитория
   уже указывает на Qdrant, Neo4j, реранкер и модель ответа.
3. Запуск в tmux (сервис сам раздаёт собранный `dist`):

   ```bash
   tmux new -d -s demo "cd $REPO_DIR && .venv/bin/python web/server/run.py --repo $REPO_DIR --mode server --host 127.0.0.1 --port 8000"
   ```

4. С ноутбука — туннель, затем http://localhost:8000:

   ```bash
   ssh -N -L 8000:127.0.0.1:8000 root@<сервер>
   ```

Остановка — только `tmux kill-session -t demo`. В режиме `server` доступны лишь
пресеты (сбалансированный — принятая конфигурация: top-16, маршрут всегда
в граф, реранкер; SetR; SEAL), одновременно не больше двух запросов
(`DEMO_MAX_CONCURRENT`).
