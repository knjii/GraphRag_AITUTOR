# Запуск на арендованном сервере

Пять команд от пустого сервера до метрик. Держите эту страницу открытой во время сессии.

---

## Перед первой сессией: один раз на своём компьютере

Создать SSH-ключ с ASCII-комментарием (кириллица в комментарии не проходит валидацию
у провайдера):

```powershell
ssh-keygen -t ed25519 -C "rag-textbook" -f $env:USERPROFILE\.ssh\intelion_ed25519
Get-Content $env:USERPROFILE\.ssh\intelion_ed25519.pub
```

Публичный ключ (вывод второй команды) вставить в панели провайдера.
Приватный файл — без `.pub` — не передавать никому.

## Сессия 1: развёртывание и пилотный прогон

### Шаг 1. Загрузить код и учебник (на своём компьютере)

```powershell
cd C:\python\rag_textbook
.\deploy\upload.ps1 -ServerIp ВАШ_IP
```

Занимает несколько минут: копируется код и один учебник на 20 МБ.

### Шаг 2. Подключиться к серверу

```powershell
ssh -i $env:USERPROFILE\.ssh\intelion_ed25519 root@ВАШ_IP
```

### Шаг 3. Развернуть окружение (на сервере, ~40 минут)

```bash
cd rag_textbook
bash deploy/bootstrap.sh
```

Скрипт поставит Docker, проброс GPU, uv, зависимости проекта, сгенерирует пароль Neo4j
и прогонит тесты. В конце — **сделайте снапшот сервера в панели провайдера**: следующие
сессии будут стартовать за минуты вместо часа.

### Шаг 4. Поднять сервисы (~10 минут)

```bash
bash deploy/services.sh up
```

Поднимает Qdrant, Neo4j, Infinity, Ollama, Phoenix, скачивает модели и проверяет
связность. В конце печатает занятую видеопамять.

### Шаг 5. Запустить пилотный прогон

Обязательно **внутри tmux** — иначе разрыв связи прервёт многочасовую индексацию:

```bash
tmux new -s pilot
bash deploy/pilot.sh
```

Отключиться от сессии, не прерывая её: `Ctrl+B`, затем `D`.
Вернуться позже: `tmux attach -t pilot`.

### Шаг 6. Забрать результаты и остановить сервер

На сервере:

```bash
bash deploy/services.sh down
shutdown -h now
```

На своём компьютере:

```powershell
.\deploy\download.ps1 -ServerIp ВАШ_IP
```

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `health` показывает ошибку у компонента | `bash deploy/services.sh logs infinity` (или `neo4j`, `qdrant`, `ollama`) |
| Контейнеры не видят GPU | `docker run --rm --gpus all nvidia/cuda:13.0.0-base-ubuntu24.04 nvidia-smi` |
| Кончилась видеопамять | уменьшить `LLM_MAX_CONCURRENCY` в `.env` до 2, перезапустить прогон |
| Индексация прервалась | просто запустить `bash deploy/pilot.sh` заново — стадии возобновляются с места остановки |
| Порвалась связь | `tmux attach -t pilot` — прогон продолжался без вас |
| Медленно идёт разбор PDF | попробовать `MINERU_BACKEND=hybrid` в `.env` |

Прогон **безопасно прерывать**. Манифест индексации и кэши вызовов моделей означают,
что повторный запуск не платит второй раз за уже сделанное.

## Что смотреть в результатах

| Файл | Что показывает |
|---|---|
| `summary.json` | время каждой стадии и утилизация GPU |
| `metrics/indexing_*.json` | сколько чанков, сколько с формулами, статистика графа |
| `metrics/retrieval_eval_baseline_*.json` | Recall@k, nDCG@k, MRR с разрезом по типам вопросов |
| `gpu_utilization.csv` | загрузка карты по времени — по ней решаем про модель побольше |
| `pilot.log` | полный лог |

Главные числа первой сессии:

1. **Время индексации** против прежних 14.5 часов на этот же учебник.
2. **Доля типизированных связей в графе** против прежних 1617 из 282 143.
3. **Первые честные Recall@k** — точка отсчёта для всех дальнейших экспериментов.
4. **Простой GPU в процентах** — если карта простаивает больше половины времени,
   узкое место не в ней, и модель побольше ничего не ускорит.

## Про JupyterLab

Он установлен в образе, но в работе не используется. Если решите им пользоваться —
не открывайте порт наружу, ходите через SSH-туннель:

```powershell
ssh -i $env:USERPROFILE\.ssh\intelion_ed25519 -L 8888:127.0.0.1:8888 root@ВАШ_IP
```

То же правило для всех остальных интерфейсов: Neo4j Browser (7474), Qdrant (6333),
Phoenix (6006) слушают только localhost и доступны через туннель.
