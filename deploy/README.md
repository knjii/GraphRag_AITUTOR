# Запуск на арендованном сервере

Пять команд от пустого сервера до метрик. Держите эту страницу открытой во время сессии.

---

## Перед первой сессией: один раз на своём компьютере

Создать SSH-ключ с ASCII-комментарием (кириллица в комментарии не проходит валидацию
у провайдера):

```powershell
ssh-keygen -t ed25519 -C "rag-textbook" -f $env:USERPROFILE\.ssh\intelion_ed25519
Get-Content $env:USERPROFILE\.ssh\intelion_ed25519.pub
```

Публичный ключ (вывод второй команды) вставить в панели провайдера.
Приватный файл — без `.pub` — не передавать никому.

## Сессия 1: развёртывание и пилотный прогон

### Шаг 1. Загрузить код и учебник (на своём компьютере)

```powershell
cd C:\python\rag_textbook
.\deploy\upload.ps1 -ServerIp ВАШ_IP
```

Занимает несколько минут: копируется код и один учебник на 20 МБ.

### Шаг 2. Подключиться к серверу

```powershell
ssh -i $env:USERPROFILE\.ssh\intelion_ed25519 root@ВАШ_IP
```

### Шаг 3. Развернуть окружение (на сервере, ~40 минут)

```bash
cd rag_textbook
bash deploy/bootstrap.sh
```

Скрипт поставит Docker, проброс GPU, uv, зависимости проекта, сгенерирует пароль Neo4j
и прогонит тесты. В конце — **сделайте снапшот сервера в панели провайдера**: следующие
сессии будут стартовать за минуты вместо часа.

### Шаг 4. Поднять сервисы (~10 минут)

```bash
bash deploy/services.sh up
```

Поднимает Qdrant, Neo4j, Infinity, Ollama, Phoenix, скачивает модели и проверяет
связность. В конце печатает занятую видеопамять.

### Шаг 5. Запустить пилотный прогон

Обязательно **внутри tmux** — иначе разрыв связи прервёт многочасовую индексацию:

```bash
tmux new -s pilot
bash deploy/pilot.sh
```

Отключиться от сессии, не прерывая её: `Ctrl+B`, затем `D`.
Вернуться позже: `tmux attach -t pilot`.

### Шаг 6. Забрать результаты и остановить сервер

На сервере:

```bash
bash deploy/services.sh down
shutdown -h now
```

На своём компьютере:

```powershell
.\deploy\download.ps1 -ServerIp ВАШ_IP
```

## Переезд на новый сервер

У хостинга нет снапшотов, а изменить размер диска можно только созданием
новой машины. Поэтому переезд — обычный сценарий, а не авария.

**Ничего невосстановимого на сервере не остаётся.** Всё, что стоит дорого,
лежит в кэшах и переносится вместе с кодом:

```powershell
.\deploy\upload.ps1 -ServerIp <новый адрес> -WithCaches
```

Затем на сервере, как обычно:

```bash
cd rag_textbook && bash deploy/bootstrap.sh && bash deploy/services.sh up
```

и восстановление индекса двумя командами вместо полного прогона:

```bash
rag-textbook ingest --stages parse,chunk,embed --force
rag-textbook ingest --stages graph --force
```

Почему это быстро: разбор берётся из `artifacts/parsed`, описания иллюстраций
и извлечённые связи — из `artifacts/cache`. Модель вызывается заново только
на проходе по связям между фрагментами.

| Что | С нуля | С кэшами |
|---|---|---|
| Разбор, чанкинг, векторизация | 9.6 мин | ~1 мин |
| Граф | 72 мин | ~4 мин |

Дольше всего идёт не восстановление, а подготовка машины: загрузка образов
(SGLang распаковывается в 47 ГБ) и весов модели — около часа, почти целиком
без участия человека.

**Что сверить перед восстановлением.** Ключ кэша извлечения зависит от
`LLM_MODEL`, `LLM_REASONING_EFFORT`, `GRAPH_EXTRACTION_PROMPT_VERSION`
и лимитов на сущности и связи; кэш разбора — от `MINERU_*` и размера чанка.
Если эти значения разойдутся, кэш не попадёт и всё посчитается заново.
Выверенные значения лежат в [`measured/server-env-measured.txt`](measured/server-env-measured.txt) —
берите `.env` оттуда, дописав пароль Neo4j, который `bootstrap.sh` генерирует
на каждой машине заново.

**Что теряется безвозвратно:** ничего. Коллекция Qdrant и граф Neo4j живут
в томах Docker и умирают вместе с сервером, но восстанавливаются из кэшей
за пять минут.

**Размер диска.** Берите не меньше 250 ГБ. На 123 ГБ свободное место дважды
падало ниже гигабайта, и один раз пришлось экстренно удалять образы, чтобы
не потерять записи Qdrant и Neo4j.

## Сессия на карте: два скрипта и ничего вручную

Смысл разделения — платить за карту только там, где она нужна. Перебор настроек
графа считается заранее и бесплатно на своём компьютере (`rag-textbook graph
offline`), на сервер едут только проверенные варианты.

```bash
bash deploy/restore.sh              # индекс из кэшей, около 5 минут
bash deploy/experiments.sh --list   # что будет проверено и на каком основании
bash deploy/experiments.sh          # весь план, около 45 минут
```

Перед первым запуском плана на новой машине выполните ещё одно:

```bash
bash deploy/baseline-env.sh
```

Он возвращает `.env` к значениям, на которых сняты прежние метрики. Без этого
часть гипотез сравнивалась бы сама с собой: в `.env.example` уже стоят порог
хабов 40 и затухание 0.8, подобранные офлайн, — то есть кандидаты, а не точка
отсчёта. Заодно скрипт выставляет настройки движка, которых в примере нет:
`SGLANG_GPU_FRACTION=0.75` и `LLM_MAX_CONCURRENCY=16`.

**`restore.sh`** поднимает сервисы, ждёт `health`, восстанавливает разбор,
векторы и граф из кэшей. Перед этим он сверяет девять настроек, входящих в ключ
кэша: разойдётся любая — и стадия графа посчитается заново за 72 минуты вместо
четырёх, молча. При расхождении скрипт спрашивает подтверждение.

**`experiments.sh`** прогоняет план проверок по убыванию ожидаемой отдачи.
Каждый шаг отмечается в `artifacts/runs/<прогон>/done`, поэтому прерывать
и запускать заново можно в любой момент — сделанное не переделывается.

| Код | Гипотеза | Основание |
|---|---|---|
| Р1 | Реранкер выбрасывает второй фрагмент пары; обязательная квота мест его защитит | с реранкером многошаговые 0.576, без него 0.703 |
| Р2 | Резерва в шесть мест мало | граф держит нужный фрагмент в первых тридцати в 81% случаев |
| Р3 | Маршрутизатор закрывает граф трети многошаговых вопросов | в граф уходят 66.7% вопросов `graph_linked` |
| Г2 | Затухание веса соседа 0.8 вместо 0.5 | офлайн-замер MRR второго шага 0.225 → 0.253 |
| Г3 | Вклад сущности взвесить редкостью | офлайн-замер доли попаданий 0.404 → 0.449 |
| К1 | Перепроверить реранкер с разбором по типам | прежнее решение принято по среднему |
| Г1 | Порог отсечения хабов 40 вместо 64 | требует пересборки графа, поэтому идёт последним |

Отдельные шаги: `--only Р1`, `--from Г2`.

### Почему восстановление идёт без `--force`

Соблазн очевидный: хранилища пусты, значит надо всё переделать. Но `--force`
переделывает и разбор — MinerU запускается заново на том же PDF. Дело не
в пяти потерянных минутах, а в том, что **текст фрагмента входит в ключ кэша
извлечения**: чуть иной текст обесценивает 1477 записей и 72 минуты работы
модели, причём молча.

На новой машине пусты не артефакты, а хранилища: коллекция Qdrant и граф Neo4j
живут в томах Docker и остаются на прежнем сервере. Поэтому `restore.sh` снимает
отметки только у стадий, которые в эти хранилища пишут:

```bash
bash deploy/reset-stages.sh embedded graphed
```

Замер на новой машине: векторизация 1151 фрагмента — **10 секунд**, сборка
графа из кэша — **3 минуты**, граф воспроизвёлся до 3944 сущностей и 4399
связей против 3977 и 4251 на прежней машине.

### Если нужно прервать индексацию

```bash
bash deploy/stop-indexing.sh
```

Не `pkill -f 'rag-textbook ingest'`: такой шаблон совпадает с командной строкой
SSH-сессии, которой этот pkill запущен, и сессия убивает сама себя. Скрипт ищет
процесс по исполняемому файлу и исключает собственный pid.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `health` показывает ошибку у компонента | `bash deploy/services.sh logs infinity` (или `neo4j`, `qdrant`, `ollama`) |
| Контейнеры не видят GPU | `docker run --rm --gpus all nvidia/cuda:13.0.0-base-ubuntu24.04 nvidia-smi` |
| Кончилась видеопамять | уменьшить `LLM_MAX_CONCURRENCY` в `.env` до 2, перезапустить прогон |
| Индексация прервалась | просто запустить `bash deploy/pilot.sh` заново — стадии возобновляются с места остановки |
| Порвалась связь | `tmux attach -t pilot` — прогон продолжался без вас |
| Медленно идёт разбор PDF | попробовать `MINERU_BACKEND=hybrid` в `.env` |

Прогон **безопасно прерывать**. Манифест индексации и кэши вызовов моделей означают,
что повторный запуск не платит второй раз за уже сделанное.

## Что смотреть в результатах

| Файл | Что показывает |
|---|---|
| `summary.json` | время каждой стадии и утилизация GPU |
| `metrics/indexing_*.json` | сколько чанков, сколько с формулами, статистика графа |
| `metrics/retrieval_eval_baseline_*.json` | Recall@k, nDCG@k, MRR с разрезом по типам вопросов |
| `gpu_utilization.csv` | загрузка карты по времени — по ней решаем про модель побольше |
| `pilot.log` | полный лог |

Главные числа первой сессии:

1. **Время индексации** против прежних 14.5 часов на этот же учебник.
2. **Доля типизированных связей в графе** против прежних 1617 из 282 143.
3. **Первые честные Recall@k** — точка отсчёта для всех дальнейших экспериментов.
4. **Простой GPU в процентах** — если карта простаивает больше половины времени,
   узкое место не в ней, и модель побольше ничего не ускорит.

## Про JupyterLab

Он установлен в образе, но в работе не используется. Если решите им пользоваться —
не открывайте порт наружу, ходите через SSH-туннель:

```powershell
ssh -i $env:USERPROFILE\.ssh\intelion_ed25519 -L 8888:127.0.0.1:8888 root@ВАШ_IP
```

То же правило для всех остальных интерфейсов: Neo4j Browser (7474), Qdrant (6333),
Phoenix (6006) слушают только localhost и доступны через туннель.
