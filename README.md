# rag_textbook

ИИ-ассистент для глубокого изучения математической и технической литературы:
работа с формулами, таблицами и иллюстрациями, дополненная графом знаний
для вопросов, требующих связать разные разделы.

## Устройство

```
PDF ──MinerU──> блоки ──обогащение──> чанки ──┬──> Qdrant  (плотный + BM25)
                                              └──> Neo4j   (граф знаний)

вопрос ──переписывание──> роутер ──┬──> гибридный поиск ──┐
                                   └──> графовый канал ───┴──> слияние ──> реранкер ──> ответ с цитатами
```

Ключевые свойства:

- **формулы и таблицы не теряются** — LaTeX и HTML из MinerU индексируются вместе
  с описанием, а не заменяются им;
- **цитаты с номерами страниц** — ответ можно проверить по учебнику;
- **лексический поиск знает русскую морфологию** — BM25 со стеммингом на стороне Qdrant;
- **граф используется по делу** — роутер включает его на вопросах, требующих связей,
  а рёбра фильтруются по PMI, чтобы граф не вырождался в клики частотных слов;
- **всё измеримо** — retrieval-метрики считаются без LLM за секунды;
- **индексация возобновляема** — падение на стадии графа не заставляет заново парсить PDF.

## Состояние

Стек развёрнут и проверен вживую на арендованном сервере с RTX 3090
(Ubuntu 24.04, драйвер 610.x, CUDA 13). Проведена сквозная индексация всего
учебника (512 страниц) с замерами ресурсов и измерением качества поиска
на эталонном наборе.

| Показатель | Прежняя версия | Сейчас |
|---|---|---|
| Индексация учебника целиком | 14.5 ч | **~40 мин** |
| Разбор + чанкинг + векторизация | часть от 14.5 ч | **9.6 мин** |
| Доля типизированных связей графа | 0.57 % | **72 %** |
| Качество поиска, recall@16 | не измерялось | **0.859** |
| Прирост от реранкера, nDCG | не измерялся | **+0.051** [+0.011; +0.093] |
| Прирост от графового канала, recall | «нет» (канал не работал) | **+0.018** [+0.006; +0.034] |

Графовый компонент переработан по итогам измерений и **даёт значимый прирост**:
шесть улучшенных вопросов из 163 и ни одного ухудшенного. На вопросах, ради
которых он и строится, recall 0.710 → 0.754. Как это получено, включая три
опровергнутые по дороге гипотезы, — в [`docs/REPORT.md`](docs/REPORT.md)
и [`docs/engineering-log.md`](docs/engineering-log.md).

## Установка

```bash
uv sync --extra dev
```

Для разбора PDF дополнительно (нужно только там, где реально парсим):

```bash
uv sync --extra parsing
```

Extra `parsing` тянет `mineru[core]` — именно с дополнением `core`, иначе
приедет оболочка без моделей и без PyTorch, и разбор не запустится.

## Инфраструктура

```bash
cp .env.example .env   # заполните NEO4J_PASSWORD
docker compose --env-file .env -f docker/docker-compose.yml up -d
```

`--env-file` обязателен: каталогом проекта Compose считает каталог
compose-файла, а `.env` лежит в корне репозитория.

Поднимаются Qdrant, Neo4j, Infinity (эмбеддер + реранкер) и Phoenix.
Все порты слушают только localhost — наружу ходите через SSH-туннель.

Генеративная модель запускается отдельно: на этапе разработки Ollama,
на этапе пилота SGLang или vLLM. Переключение — сменой `LLM_BASE_URL`,
код не меняется.

### Развёртывание на арендованном сервере

```bash
.\deploy\upload.ps1 -ServerIp <адрес>     # с вашей машины
```

Затем на сервере:

```bash
cd rag_textbook && bash deploy/bootstrap.sh && bash deploy/services.sh up
```

`bootstrap.sh` идемпотентен и умеет обходить особенности хостинга: выбирает
доступное зеркало PyPI, снимает удержание с контейнерных пакетов NVIDIA,
проверяет проброс видеокарты в контейнеры. Подробности — в
[`deploy/README.md`](deploy/README.md).

## Работа

```bash
# проверить, что всё поднялось
rag-textbook health

# проиндексировать корпус из PDF_DIR
rag-textbook ingest

# задать вопрос
rag-textbook ask "Как связаны сингулярное разложение и метод главных компонент?" --show-context

# собрать эталонный набор из проиндексированных чанков
rag-textbook goldset build --single 100 --multihop 50

# измерить качество поиска
rag-textbook eval run

# проверить, даёт ли граф прирост
rag-textbook eval ab --experiment graph

# статистика графа знаний
rag-textbook graph stats

# перебрать настройки обхода графа по локальному кэшу — без сервера и GPU
rag-textbook graph offline
```

Последняя команда работает на ноутбуке. Она восстанавливает граф из кэша
извлечения и меряет то единственное, чего системе не хватает: если дать графу
первый фрагмент пары, на каком месте окажется второй. Разбор промахов показал,
что все неудачи на многошаговых вопросах устроены именно так — один фрагмент
найден, второй нет. Перебор занимает секунды, поэтому на арендованную карту
едут только те варианты, которые уже что-то показали.

Сервис для пилота:

```bash
uvicorn rag_textbook.api.app:app --host 127.0.0.1 --port 8000
```

## Мониторинг и утилизация

```bash
rag-textbook ingest --monitor          # метрики ресурсов с разметкой по стадиям
rag-textbook bottlenecks <каталог>     # во что упирается каждая стадия
rag-textbook bench                     # пропускная способность сервера инференса
```

Режим обхода корпуса задаётся `INDEXING_MODE`: `stage` (по умолчанию) обрабатывает
корпус по стадиям — крупные батчи и один потребитель видеопамяти в каждый момент;
`document` экономнее по оперативной памяти. Результат обоих режимов идентичен.

Для пробных прогонов объём ограничивается диапазоном страниц
(`MINERU_PAGE_START`, `MINERU_PAGE_END`) — разбор самая дорогая стадия,
и сокращать нагрузку осмысленно именно там. Диапазон входит в ключ кэша
разбора, поэтому пробный прогон не подменяет собой полный.

## Подводные камни, которые уже учтены

Эти настройки выглядят мелочью, но каждая из них ломала работу целиком.

| Параметр | Значение | Почему именно так |
|---|---|---|
| `LLM_REASONING_EFFORT` | `none` | рассуждающая модель тратит весь лимит токенов на размышление и возвращает пустой ответ — граф остаётся без связей |
| `EMBEDDING_MODEL` | `BAAI/bge-m3` | `Qwen3-Embedding` построена на архитектуре `qwen3`, которую не знает ни один выпущенный образ Infinity |
| `EMBEDDING_BASE_URL` | без `/v1` | Infinity отдаёт OpenAI-совместимые пути в корне |
| `MINERU_LANG` | `east_slavic` | значения `ru` MinerU не знает и падает с кодом 2 |
| `EMBEDDING_QUERY_PREFIX` | пусто | у `bge-m3` симметричное обучение, инструктивный префикс мешает |
| `SGLANG_GPU_FRACTION` | `0.75` | батч упирается в слоты состояния mamba, а не в KV-кэш: 0.55 даёт вдвое меньшую пропускную способность |
| `RETRIEVAL_TOP_K_LINKING` | `16` | связывающему вопросу нужно два эталонных фрагмента, и обычная квота вмещает вдвое меньше ответов |
| `RETRIEVAL_GRAPH_CANDIDATE_QUOTA` | `6` | без резерва находки графа не доезжают до реранкера, и его вклад равен нулю |

Версии образов закреплены и должны оставаться свежими: старый образ с новой
моделью не деградирует, а не стартует вовсе.

## Оценка

Схема из трёх слоёв описана в [`docs/MIGRATION-PLAN.md`](docs/MIGRATION-PLAN.md)
и в памяти проекта:

1. **Свой корпус** — эталонный набор с идентификаторами эталонных чанков,
   метрики Recall@k, nDCG@k, MRR. По ним принимаются решения.
2. **OmniDocBench** — качество разбора PDF: формулы, таблицы, порядок чтения.
   Прогоняется скриптом [`deploy/omnidocbench.sh`](deploy/omnidocbench.sh):
   он скачивает набор, разбирает страницы теми же настройками, что и рабочий
   корпус, и считает метрики в контейнере разработчиков бенчмарка.
3. **Публичный multi-hop бенчмарк** — сопоставимость с опубликованными базлайнами.

Важно: набор, сгенерированный моделью, — это черновик. Перед использованием как
эталона его нужно просмотреть вручную и проставить `verified: true`.
Набор меньше 100 вопросов даёт доверительный интервал шире типичного эффекта,
и различия между конфигурациями по нему считать нельзя — команда `eval ab`
предупреждает об этом явно.

## Офлайн-работа по слепку

Дорогая часть замеров требует арендованного GPU, но перебор **порядка и отбора**
его не требует. `deploy/capture.sh` за одну серверную сессию снимает слепок:
кандидаты каналов с рангами и баллами, баллы реранкера по широкому окну,
итоговый отбор по каждому вопросу.

```bash
uv run rag-textbook eval replay capture/trace.jsonl
```

Дальше веса слияния, `rrf_k`, дедупликация, разнообразие выдачи, режим
реранкера и ширина окна перебираются на ноутбуке бесплатно — на тех же числах,
что видел сервер.

Всё, что меняет **состав** кандидатов (обход графа, режим затравок, разложение
вопроса, другая модель), по слепку не проверяется: попытка прерывается
с перечислением нарушивших настроек. Граница не условность — офлайн-подбор,
перешедший её однажды, стоил принятого и вредного значения порога хабов.

Перед перебором `eval replay` сверяет честность: воспроизведение с рабочими
настройками обязано повторить серверную выдачу. Не повторяет — перебор
не запускается.

## Тесты

```bash
uv run pytest -q
```

Тесты не требуют ни GPU, ни Qdrant, ни Neo4j, ни сервера инференса: внешние
клиенты подменяются детерминированными заглушками, векторное хранилище —
реализацией в памяти. Рабочий `.env` они намеренно не читают: путь к файлу
задаётся переменной `RAG_ENV_FILE`, иначе результат зависел бы от того, лежит
ли рядом чужой файл настроек.

## Ограничения текущего состояния

- **Эталонный набор наполовину мерит не то.** Ручная проверка 20 связывающих
  вопросов: 35% действительно требуют двух фрагментов, 50% отвечаются одним,
  15% испорчены. По всему набору у 18.8% связывающих вопросов хотя бы один
  эталонный фрагмент негоден — оглавление или страница упражнений. Отставание
  этого типа (0.734) наполовину создано разметкой. Сравнения конфигураций между
  собой остаются честными: обе стороны видят одни и те же вопросы.
- **Эталонный набор почти не вычитан человеком.** 388 вопросов сгенерированы
  моделью, проверено 29.
  Для сравнения конфигураций между собой этого достаточно — обе стороны видят
  одни и те же вопросы. Для заявлений об абсолютном качестве продукта нет.
- **Измерено качество поиска, а не качество ответа.** Retrieval-метрики говорят,
  дошёл ли нужный фрагмент до контекста. Генеративные метрики пока остаются
  в прежнем `src/deepeval_eval.py`.
- **Разбор PDF измерен только на чужом языке.** На OmniDocBench (486 страниц,
  движок `pipeline`) получено: формулы CDM 0.887, таблицы TEDS 0.883, текст
  0.039. Осмысленны здесь формулы и таблицы — LaTeX и HTML языконезависимы;
  русского подмножества в бенчмарке нет, поэтому текст и порядок чтения к нашему
  корпусу переносятся плохо.
- **Замеры на одном учебнике**, одна предметная область, один язык.
- **Отбор из найденного улучшить не удалось.** Четыре группы гипотез
  (разнообразие выдачи, условный реранкинг, ширина окна реранкера, веса
  слияния) отвергнуты офлайн-перебором по слепку. Разбор промахов показал
  почему: 56 из 100 недостающих фрагментов вообще отсутствуют в пуле
  кандидатов — это потеря доступа, перестановкой она не лечится.
- **Прирост от графа скромный** — 6 улучшенных вопросов из 163. Он положителен,
  значим и никого не ухудшает, но это начало, а не финал. Семь гипотез
  о том, как его увеличить, проверены на сервере и **не подтвердились ни одной**;
  разбор причин — в [`docs/REPORT.md`](docs/REPORT.md), §8.2.
- **Офлайн-подбор настроек обхода не переносится на продукт.** Порог 40 давал
  на локальном замере второго шага MRR +0.075 и подтверждался на отложенной
  половине пар, а на сервере оказался значимо вредным: обрезка хабов убирает
  сущности и из полнотекстового поиска затравок, чего офлайн-модель не видит.
  Возвращён порог 64. Офлайн годится, чтобы дёшево **отбрасывать** гипотезы,
  но не подтверждать их.
