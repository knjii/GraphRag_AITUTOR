**Правило выбора графа для К4** записано до прогонов. Берётся граф
с наибольшим recall@16 на связывающих вопросах части **dev** среди
base, K1A, K1C, K3book и K3sec. При равенстве до третьего знака
выбирается первый в этом списке, то есть более простой. Часть test
в выборе не участвует, поэтому вердикт К4 на test честный.

**Вердикт.** Гипотезу принимает только часть test. На dev вердикт
помечен «только выбор варианта». Отсутствующий прогон считается «не
ставился», а не провалом. Мера — recall@16 на срезе. Рядом печатаются
полнота пары (full@16) и объём контекста: вариант, выигравший длиной
фрагментов, не принимается (SetCE, бюджет токенов).

**Почему К6–К8 сразу онлайн.** По плану серии их сначала отсеивает
слепок. Но новый слепок снимается только в день 2 (`trace-r2.jsonl`),
а он по MML, не по v2. Прогон стоит 20 минут, около 12 ₽. Это дешевле,
чем допуск офлайн-вывода по пяти условиям. К8 выходит за пул и так
проверяется только онлайн.

**Судья.** 27B не помещается на карту рядом с 4B и поиском. Поэтому
ответы снимаются без судьи, затем поднимается один llama.cpp,
и `scripts/judge_saved.py` оценивает сохранённые файлы (задача 029).
Допуск — сверка с ручными оценками 2026-09-17: 110 ответов
на 65 вопросов, мера «верность». Не допущен — судейских чисел нет
вовсе, выводы только по recall и объективным мерам.

Размышление гасится ключами движка: `--chat-template-kwargs`,
`enable_thinking=false`. Клиент `chat_template_kwargs` не передаёт,
и это не меняли. Контекст судье обрезается до 6000 знаков, ответ —
до 2000. Для 16 фрагментов это меньше половины контекста, поэтому
«опора» судьи сравнима между вариантами, но не абсолютна.
