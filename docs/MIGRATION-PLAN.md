## J. Намеренно не перенесено

Три подсистемы прежней версии в новый пакет не переехали. Это осознанные решения,
а не пропуски, и каждое обратимо.

### J1. KET-RAG (отбор core/periphery)

**Что было:** гибридный kNN-граф пассажей, отбор «ядра» по центральности,
LLM-экстракция только на ядре (30% чанков), правиловая — на периферии.

**Почему снято:**
- цель — сократить число вызовов LLM — теперь достигается иначе: кэш экстракции
  по `chunk_hash + модель + версия промпта` плюс параллельные вызовы. Кэш даёт
  экономию на **повторных** прогонах, которых при отладке большинство, а KET
  экономил только на первом;
- сам отбор стоил 2580 с на учебник, из них 43 минуты — повторное вычисление
  эмбеддингов, которые уже лежали в хранилище;
- `_build_semantic_neighbors` строил плотную матрицу N×N: 50 МБ на 3533 чанках
  и около 40 ГБ на 100 тысячах. Это жёсткая стена по масштабу;
- правиловая экстракция на периферии давала узлы-токены, из которых и складывались
  клики co-occurrence — то есть KET активно ухудшал качество графа.

**Как вернуть, если понадобится:** отбор ядра логично делать не отдельным
kNN-графом, а по уже посчитанным метрикам — например, брать чанки с наибольшим
числом типизированных связей после первого прохода. Это дёшево и не требует N×N.

### J2. Keyword-канал графа (`G_k`, узлы `:Keyword`)

**Что было:** отдельные узлы ключевых слов с эмбеддингом, равным среднему
эмбеддингов предложений, и `theta`-слияние с канадом сущностей.

**Почему снято:** узлы `:Keyword` содержали те же строки, что и `:Entity`,
то есть дублировали сущности; эмбеддинг усекался до 256 измерений и сравнивался
косинусом на стороне клиента; лексический поиск теперь закрыт sparse-векторами
Qdrant с русским стеммингом, что делает канал избыточным.

**Как вернуть:** при необходимости — как vector index на `:Entity` в Neo4j 5.11+,
без отдельного типа узлов.

### J3. Генеративные метрики DeepEval

**Что было:** `src/deepeval_eval.py` (1391 строка) с Answer Relevancy,
Faithfulness, Contextual Precision.

**Почему пока не перенесено:** новый харнесс закрывает метрики **поиска** —
именно их не хватало для принятия решений. Генеративные метрики остаются
полезными, но требуют более сильного судьи, чем локальная 4B (разброс между
прогонами превышал искомый эффект). Модуль остаётся в `src/` до переноса.

## Порядок выполнения

1. A (окружение) → 2. B (конфиг) → 3. C (парсинг/чанкинг) → 4. D (клиенты моделей) →
5. E (хранилища) → 6. F (граф) → 7. G (поиск) → 8. H (оценка) → 9. I (сервис).

Пункты, требующие GPU и внешних сервисов, реализованы и покрыты тестами
на заглушках; проверка «в живую» — на арендованном сервере.

## Что проверяется автоматически

`pytest` — 67 тестов, выполняются без Qdrant, Neo4j, Ollama и Infinity.
Отдельно покрыты регрессии на конкретные дефекты прежней версии:

- сохранность LaTeX и HTML при наличии описания от модели зрения;
- пустая переменная окружения не включает флаг;
- маскирование пароля в `repr` и `model_dump`;
- запрет многохопового обхода по `CO_OCCURS`;
- отсев co-occurrence по PMI;
- отсутствие рёбер у правилового экстрактора;
- переписывание вопроса-продолжения по истории;
- изоляция истории диалога между пользователями;
- идемпотентность повторной индексации;
- предупреждение о недостаточном размере выборки при сравнении конфигураций.
