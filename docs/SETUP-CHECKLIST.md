### Про JupyterLab и прочее дополнительное ПО

Не подключаем. Наша работа — пакетные команды (`docker compose`, `rag-textbook ingest`,
`rag-textbook eval run`), а не интерактивные ноутбуки. JupyterLab добавил бы открытый
порт, который нужно защищать, съел бы память и, главное, провоцировал бы писать код
вне репозитория. Именно так в прошлой версии проекта появились неверсионируемые
`app.py`, `preflight.py` и `backfill_graph_from_chroma.py`.

Если интерактивный разбор всё же понадобится — `pip install jupyterlab` занимает
полминуты в любой момент. Решение обратимое.

### Ошибка «Ключ невалиден: 'ascii' codec can't encode characters»

Причина — кириллица в комментарии ключа. `ssh-keygen` подставляет туда `имя@компьютер`,
а имя пользователя `Максим` записан кириллицей. Валидатор провайдера принимает только ASCII.
На саму криптографию комментарий не влияет.

Решение — сгенерировать отдельный ключ с явным ASCII-комментарием:

```powershell
ssh-keygen -t ed25519 -C "rag-textbook" -f $env:USERPROFILE\.ssh\intelion_ed25519
Get-Content $env:USERPROFILE\.ssh\intelion_ed25519.pub
```

Подключение потом:

```powershell
ssh -i $env:USERPROFILE\.ssh\intelion_ed25519 root@<IP>
```

## Блок 5. Что делаю я после получения доступа

Разведывательная сессия, примерно 2–3 часа GPU-времени (около 100 ₽):

1. Разворачиваю окружение: `uv sync`, `docker compose up -d`, модели в Ollama.
2. `rag-textbook health` — убеждаюсь, что все зависимости отвечают.
3. Делаю снапшот сервера, чтобы следующие сессии начинались за 3 минуты, а не за час.
4. Индексирую **один** учебник с замером каждой стадии.
5. Сравниваю с baseline (14.5 ч на учебник) и уточняю оценку по всему корпусу.
6. Останавливаю сервер и присылаю отчёт с реальными числами.

Только после этого запускаем полную индексацию корпуса.

## Блок 6. Порядок первых экспериментов

Зафиксирован заранее, чтобы не менять два параметра одновременно:

1. **Baseline** — индексация, сборка эталонного набора, `eval run`.
   Получаем первые честные Recall@k и nDCG@k.
2. **Граф вкл/выкл** — `eval ab --experiment graph`. Отвечает на главный вопрос проекта.
3. **Реранкер вкл/выкл** — `eval ab --experiment reranker`. Проверяем мою гипотезу,
   что он даёт больше графа на однохоповых вопросах.
4. **Backend MinerU** — `pipeline` против `hybrid`. Скорость против точности разбора.
5. **KET** — возвращаем и меряем по двум осям: экономия времени индексации
   и потеря (или её отсутствие) в качестве поиска.

Между шагами меняется ровно один параметр. Иначе результат невозможно интерпретировать.
