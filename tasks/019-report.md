## 1. Находки по приоритету

### P1. Неверная математика получает полный балл

`rag_textbook/rewards/formula.py:234`, `:249`, `:252`, `:481`: удаление разделителей матрицы и группирующих скобок уничтожает структуру выражения. Эталон `$$y=\frac{ab}{c}$$` и ответ `$$y=\frac{a}{bc}$$` дают `expected=carried=1`, награду **1.0**. Эталон `$$A=\begin{bmatrix}a&b\\c&d\end{bmatrix}$$` и ответ `$$A=\begin{bmatrix}a&b&c&d\end{bmatrix}$$` также дают **1.0**, хотя размерность изменилась с 2×2 на 1×4. Ограничение дробей уже описано в docstring, но от этого целевая функция не становится корректной.

Модель может менять знаменатель и форму матрицы без потери награды. Правка: сохранить границы аргументов `frac`, строк и столбцов; нормализовать оформление отдельно от структуры. Добавить отрицательные регрессионные пары, не требуя общего символьного решателя.

### P1. При невидимом эталоне угадывание выгоднее обоснованного отказа

`rag_textbook/rl/env.py:98–103`, `:111`; `rag_textbook/rewards/composite.py:248`, `:252–264`: при отсутствии visible_gold reference заполняется исходными gold-фрагментами. Флаг отсутствия влияет на ветку отказа, но не отключает формульную награду. Невидимая формула даёт **+1.0**, распознанный отказ **+0.5**. Это учит извлекать ответ из памяти/угадывать независимо от контекста. В прочитанном наборе **11/388** таких эпизодов; у **7** действительно отсутствует хотя бы одна значимая формула reference (например, `1342ab6e90c1066e`: 3 из 7).

Кроме того, visible_gold определяется наличием ID, а reference берётся из полного `Chunk.text`. Усечение в `rag_textbook/generation/answering.py:120` может убрать сам ответ. CPU-пример с окном 512: context **816** символов, reference **3209**, формула `u=v+w` только в reference, но флаг **True**. Среди 388 реальных эпизодов такой случай с True не найден.

Правка: строить эталон из фактически показанного текста, хранить доступность ответа явно. Для недоступного ответа использовать отдельную цель отказа, не дающую большего балла за невидимые формулы; не приравнивать наличие ID к наличию ответа.

### P1. Максимум награды достижим копированием контекста; повтор вопроса тоже оплачивается

`rag_textbook/rewards/composite.py:197`, `:258–268`, `:271–286`: короткий дамп контекста **158** символов получает **1.3**, включая лишнюю формулу. Она не foreign, поскольку есть в контексте; одна лишняя формула не превышает allowance=2, длина ниже 1800. Повтор вопроса получает **0.3** за пересечение слов с контекстом и самим вопросом. `sentence_support` проверяет лексическое пересечение, а не наличие ответа.

Первый перенос из 10 эталонных формул приносит **0.73**, остальные девять вместе добавляют только **0.27**. Все формулы выгоднее при прочих равных, но небольшой рост длины/штрафов легко делает неполный ответ предпочтительным. Ответ одной формулой без объяснений получает **1.0**, поскольку no_prose penalty по умолчанию нулевой.

Правка: убрать бонус за буквальный повтор вопроса, проверять ответность отдельно от лексической опоры, пересмотреть вес первого переноса и плату за лишние формулы. Нужны предпочтения «полный ответ > частичный > вопрос/дамп», закреплённые тестами; простое усиление штрафа длины короткий дамп не исправит.

### P1. Разбиение склеек удаляет выдуманную часть ответа

`rag_textbook/rewards/formula.py:453–473`: если найдены минимум две формулы источника, `_split_dumps` заменяет всю формулу этими совпадениями. Остаток не оценивается. Ответ `$$a+b=c\quad d+e=f\quad \zeta\omega\psi\theta=\alpha\beta\gamma$$` при эталоне `$$a+b=c$$ и $$d+e=f$$` получает **1.0**, `carried=2`, `answer_formulas=2`, `foreign=0`.

Правка: после извлечения совпадений сохранять и проверять непокрытые участки; не выбрасывать исходную формулу до проверки чужих символов.

### P2. Импортированный goldset обходит фильтрацию leaky

`rag_textbook/rl/env.py:76`, `:98`; `rag_textbook/evaluation/goldset.py:581`: загрузка не применяет verdicts, `looks_leaky` или `references_numbering`. Проверки при генерации новых вопросов (`goldset.py:429`, `:433`, `:474`, `:477`) не защищают импортированные вопросы. Синтетический вопрос «Как записана формула (8.24)?» проходит в эпизод: `references_numbering=True`, но `looks_leaky=False`.

В локальном mml-test **11** вопросов с нумерацией; все **3** ID, помеченные leaky в verdicts, присутствуют: `1c410c5463c96476`, `33c2411443bc48ef`, `c8e2e79865aedbdf`. Это подтверждает отсутствие очистки, но **не доказывает их наличие в train**: прочитан именно test-набор. Путь построения допускает их в train при соответствующем разбиении документов. Нумерация сама по себе не раскрывает текст ответа, но создаёт зависимость от конкретного источника.

Правка: перед построением эпизодов исключать явно отклонённые ID и применять согласованную политику нумерации к импортам; сохранять счётчики причин исключения.

### P2. Доллары теряют корректные формулы и выбирают прозу

`rag_textbook/rewards/formula.py:36`, `:152`, `:183–199`: глобальное свёртывание трёх и более долларов смешивает дефект chunker с законной границей двух display-блоков. `$$a+b=c$$ $$d+e=f$$` даёт две формулы, а `$$a+b=c$$$$d+e=f$$` — только `a+b=c`. При потерянном открывающем разделителе `a+b=c$$ и $$d+e=f$$` извлекается только строка ` и `; настоящая вторая формула пропадает. Один русский союз не признаётся подозрительной прозой.

Правка: разбирать границы блоков до исправления лишних долларов; оценивать математическое содержимое обеих чётностей и сохранять валидные хвостовые блоки. Добавить отдельные случаи `$$$$` и оборванного начала.

### P2. Длинный отказ снимает штраф; распознавание зависит от четырёх подстрок

`rag_textbook/rewards/composite.py:248`; `rag_textbook/evaluation/answers.py:120`, `:200`: при видимом эталоне «Недостаточно информации для ответа.» получает **−0.5**, тот же отказ с вежливым продолжением длиной **456** — **0.0**: после 400 символов ветка отказа не работает. При невидимом эталоне «В контексте нет информации для ответа.» получает **0.0**, а «Недостаточно информации для ответа.» — **+0.5**.

Правка: отделить определение отказа от ограничения длины; длину штрафовать независимо. Расширить проверку смысловых вариантов и смешанных ответов, не ограничиваться четырьмя буквальными маркерами.

### P2. Ровно достигнутый лимит ошибочно считается обрывом даже с EOS

`scripts/train_grpo.py:55–57`, `:65`, `:72`: проверяется только `len(completion_ids) >= max_completion_tokens`. При лимите **3**, IDs `[100, 101, 151645]` и правильном тексте `$$a+b=c$$` main возвращает **−1.0**, хотя последний токен — EOS Qwen. Format для того же вызова возвращает **+1.0**. Без completion_ids штраф обрыва вообще не включается; предел символов не заменяет предел токенов. В проверенном TRL 0.24.0 callback получает IDs, а собственная проверка усечения TRL учитывает EOS/PAD.

Правка: учитывать причину окончания либо последний EOS/PAD и унифицировать общие ограничения main/format, если format задуман как контроль с теми же воротами. Пример с 3 токенами проверяет ту же границу, что 768/768.

### P2, условный риск. Совместимость TRL не подтверждена установленным стеком

`scripts/train_grpo.py:192`, `:234–245`: `_supported` отбрасывает любое отсутствующее поле, в том числе критические `loss_type`, `scale_rewards`, `vllm_mode`. Печать списка не предотвращает обучение с другими defaults. В доступном Python **TRL/torch/transformers отсутствуют**, поэтому утверждать совместимость установленной GPU-версии нельзя. В исходниках **0.24.0 и 1.13.0** критические поля Dr.GRPO поддерживаются; реального выпадения этих полей здесь не показано. Комментарий о появлении `vllm_mode` только в 1.x неверен: поле уже есть в 0.24.0.

Правка: требовать критические поля, разрешать пропуск только известных необязательных; записывать версии и итоговый config. Проверку реального GPU-стека провести отдельно до длительного запуска.

### P3. Probe ограниченно описывает стоимость server-режима

`scripts/train_grpo.py:197–230`, `:314`: `--probe` ограничивает шаги **20**, но таймер включает только `trainer.train()`, исключая загрузку модели и сохранение адаптера. `prompt_tokens_median` считается по первым **64** эпизодам; CUDA peak относится к текущему процессу, не к отдельному vLLM server, и предварительно не сбрасывается. Делитель скорости — запрошенные steps, а не фактический global_step. Поэтому probe не измеряет полную стоимость запуска или память обоих процессов. При ошибке обучения `probe.json` не записывается; это не журнал неудачных проб.

Правка: явно подписать область измерений, писать фактические шаги, версии и стадии; для server учитывать ресурсы отдельного процесса отдельно. Не использовать этот peak как суммарную потребность двух карт.

## 2. Проверенное и признанное верным

- Смена `settings.prompts.qa_system` сама по себе не ломает удаление инструкций: построение system в `rag_textbook/generation/answering.py:204` и prefix в `rag_textbook/rl/env.py:93` используют одну настройку. Пример с формулой в инструкции подтвердил её отсутствие в reward context. Файл deploy/prompts не читался. Fallback при несовпадении prefix оставляет весь system — это потенциальный риск будущего изменения сборки, не текущая воспроизведённая ошибка.
- `\mathbf{x}+y=z` и `x+y=z`, `\min(x,y)` и `min(x,y)`, матрица bmatrix и та же матрица в `\left[...\right]` совпадают. Пробелы нормализуются. `a+b=c` и `c=a+b` имеют разные canonical tokens, но перенос засчитывается отдельным `_flip_equation` (`formula.py:481`).
- `x^2`/`x_2`, `a-b`/`b-a` различаются канонически. Однако они короче MIN_TOKENS=5 и отдельно не входят в expected. `x_1+y_1`/`x_2+y_1` не дают точного переноса; soft similarity **0.857143** всё же считает ответ relevant. Это эвристика похожести, не математическая эквивалентность.
- `$$$a+b=c$$$` восстанавливается в одну формулу. Два display-блока с пробелом извлекаются корректно.
- Повторы действительно штрафуются (`composite.py:71–117`): два повторения «Формула приведена в контексте. » дают share **0**, три — **0.673913** и штраф **−1**. Для `а`×100 share **0.84**, для `да `×100 — **0.96321**. Граница штрафа строгая `share > 0.2`; канонические дубли требуют минимум 6 единиц, поиск длинных циклов — минимум 3 повтора блока 12–200 символов. Два повтора не обязаны штрафоваться.
- Ворота отсекают пустоту, утечку reasoning, чрезмерную латиницу и длину, но не оценивают ответность. `format_reward('?')`, `format_reward('123')`, `format_reward('Ответ будет позже.')` равны **1**. Это допустимо как слабый контроль формата, но не как самостоятельный показатель качества.
- `scripts/train_grpo.py:141–159`: бюджет prompt **12288−768=11520**; длинные эпизоды исключаются до передачи trainer, не обрезаются с сохранённым старым reference. Для проверенного mml-test все **388** проходят: 6353 / 8447 / 9422 / 10386 токенов (min / верхняя медиана / p95 / max). Максимум вместе с completion — **11154**, запас **1134** до max_seq_length.
- Длины посчитаны `tokenizers==0.23.1` с официальным tokenizer Qwen3.5-4B, revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`. Вручную воспроизведена проверенная текстовая ветка chat_template для system/user с `enable_thinking=False`, включая пустой `<think>...</think>` в префиксе assistant; `add_special_tokens=False`. Все эпизоды имеют эти роли. Полный вызов Transformers недоступен; это точная проверка данной текстовой ветки, не запуск model.generate. Готовая строка prompt не требует второго chat template.
- `loss_type='dr_grpo'`, `scale_rewards=False`, `beta=0.0` соответствуют описанию Dr.GRPO: постоянный знаменатель вместо длины ответа, отсутствие деления advantages на групповое std, без KL. В TRL **0.24.0** False преобразуется в `none` (`grpo_config.py:644`), loss делится на `batch_size * max_completion_length` (`grpo_trainer.py:1736`); соответствующая семантика есть в **1.13.0** (`grpo_config.py:1065`, `grpo_trainer.py:3256`). Это проверка исходников, не установленного GPU-стека.
- При G=4 и grad_accum=4 на одной карте получается **16 completions, 4 группы** на шаг оптимизатора, а не одна. Это **не ошибка advantages**: TRL 0.24.0 считает среднее через `view(-1, num_generations)` и вычитает его внутри каждой группы (`grpo_trainer.py:1488–1508`). Accumulation объединяет градиенты нескольких корректных групп; sampler сохраняет группировку. Утверждение задачи «если не одна, группа неправильная» не подтверждается.
- CLI отклоняет `--vllm-mode server` без `--vllm` и комбинацию vLLM с Unsloth (`train_grpo.py:308–313`). В server-режиме sleep mode отключён; используются стандартные endpoint-настройки TRL, отдельных CLI host/port нет. Подключение сервера, синхронизация весов и реальный расход GPU не проверялись.

## 3. Численные границы и воспроизводимые эксплойты

Для default RewardConfig обычная ветка имеет формульный вклад не более **1.0**, поддержку не более **0.3**. Partial (не более 0.3) добавляется только при отсутствии carried, поэтому суммировать 1.0+0.3+0.3 нельзя. При expected=0 формульный вклад нулевой, максимум остаётся **0.3** за поддержку. Штрафы ограничены: foreign 0.5, offtarget 0.4, latin 0.5, repetition 1.0, length 0.3. Следовательно, гарантированная внешняя оценка полной награды — **[−2.7; 1.3]**. Верхняя граница достигнута дампом ниже; **−2.7 — консервативная нижняя оценка, совместная достижимость всех штрафов не доказана**. Ранние ворота дают −1, распознанный отказ ±0.5, то есть остаются внутри интервала.
