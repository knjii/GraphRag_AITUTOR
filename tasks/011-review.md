# Проверка задачи 011: код ПРИНЯТ, вывод ИЗМЕНЁН исследователем

Код: `PPRGraph`/`rank_ppr` корректны, 25 тестов графа проходят, ruff чистый.

## Изъян сравнения

PPR считался на офлайн-графе (восстановлен из кэша, 47 пропусков) с
затравками HippoRAG-стиля, а сравнивался с каналом `graph` из слепка —
рабочий граф Neo4j и его затравки. Разница алгоритмов смешана с разницей
графа и затравок. Лимит Codex был исчерпан (97% окна), поэтому честный
контроль посчитал исследователь (`ppr_fair.py`, один граф, одни затравки):

| вариант | recall@30 | эталонов | «только из графа» |
|---|---|---|---|
| канал из слепка | 0.2345 | 166 | 41 |
| один шаг, офлайн, те же затравки | 0.2500 | 176 | **49** |
| PPR 0.3 / 1.0, те же затравки | 0.2552 | 174 | 44 |

PPR − один шаг: recall +0.005 [−0.023; +0.034], «только из графа»
на вопрос −0.013 [−0.041; +0.018]. Один шаг офлайн − слепок: recall
+0.015 [−0.009; +0.040], «только из графа» +0.021 [−0.005; +0.046], p=0.145.

## Вывод

- **PPR как алгоритм внутри одной книги ничего не добавляет** к обходу
  на один шаг; в опыте с известным первым фрагментом он хуже по MRR
  (0.111 против 0.160). Как рычаг — отброшен для одной книги;
  на библиотеке — проверяется в спринте 4 вместе со всей схемой.
- **Кандидат — затравки**: лемматизированные понятия вопроса плюс верх
  base. Прирост не значим (p=0.145); офлайн его не подтверждает, это
  гипотеза для сервера.
- Выбор «лучшего из 12» на тех же вопросах — оптимистичная оценка;
  отмечено в отчёте, согласен.
