## Что сделано по файлам и границы проверки

- `scripts/check_day1.py`: CLI на стандартной библиотеке, без сети, импорта кода проекта и исполнения команд. AST Typer/argparse: имена команд/опций, обязательные аргументы (включая группы argparse), отсутствие значений; aliases config; явные входы/выходы и перенаправления. Выводит шаг, команду, основание со строкой; ошибки дают код 1, одни неизвестные — 0. Запуск: `C:\python\rag_textbook\.venv\Scripts\python.exe scripts/check_day1.py [путь_к_сценарию]`.
- `tests/test_check_day1.py`: настоящий сценарий, синтетические неизвестные команды/опции/env, обязательные аргументы/группа, отсутствие значения, отсутствующий и поздно создаваемый вход, производители CLI/скрипт/перенаправление, посторонний соседний выход, динамические пути, heredoc/комментарии, отсутствие исполнения анализируемого Python, коды возврата.
- `tasks/018-report.md`: пополнялся по ходу реализации, чтения и проверки. Правки deploy и probe_compare не внесены; выше перечислены предложения исследователю.

Это ограниченный анализатор, не интерпретатор Bash. Порядок производителей лексический: выполнение функций по PLAN, ветвления, пропуск шагов через done/--only/--from и успешность команд не моделируются. Простые присваивания/массивы раскрываются; область видимости, циклы и command substitution полностью не вычисляются. Для неизвестного массива обязательные аргументы отмечаются как неизвестные. Несколько команд в одной строке полноценно не разбираются: анализируется первая найденная команда проекта. Содержимое heredoc не анализируется. Произвольные cat/tee, код Python, неявные выходы и чтение внутри программы не покрыты; явные входы определяются по Path и небольшому списку файловых опций. --out может быть префиксом, поэтому производные имена получают «неизвестно», а не подтверждение существования. Внешние файлы preflight также получают «неизвестно», если отсутствуют локально.

AST-поддержка ограничена объявлениями текущего проекта: нет полной модели Click/Typer, динамического создания argparse, наследуемых парсеров, проверки choices/типов значений, взаимоисключения одновременно переданных опций и всех вариантов nargs. Обязательная группа проверяется на наличие хотя бы одного участника. Стандартные переменные окружения исключены явным списком. SERVER-DAY-1.md автоматически не проверяется (опциональная часть). Эти ограничения оставляют пропуски; зелёная проверка не заменяет ручной аудит повторного запуска, свежести проб и работоспособности окружений.
