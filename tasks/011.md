# Задача 011: PPR по схеме HippoRAG 2 на офлайн-графе

## Зачем

План графа v2 — схема HippoRAG 2: граф «фрагмент — понятие» и
Personalized PageRank (PPR) вместо нынешнего обхода на один шаг
(`rag_textbook/evaluation/graph_offline.py:231`, `rank_from_passage`).
Прежде чем платить за сервер, проверяем механизм офлайн — по кэшу
извлечения и слепку поиска. Офлайн годится, чтобы **отбросить** идею,
но не чтобы её подтвердить.

## Что сделать

1. **PPR** в `rag_textbook/evaluation/graph_offline.py` — новая функция
   рядом с `rank_from_passage`, без внешних зависимостей (степенной метод):
   - двудольный граф из `OfflineGraph`: узлы-фрагменты и узлы-сущности,
     рёбра «фрагмент упоминает сущность» (вес — `log(1+count)`), плюс
     рёбра между сущностями из `neighbours` (вес — параметр);
   - вероятность возврата `alpha` (по умолчанию 0.5, как в HippoRAG 2 —
     проверь в статье `%TEMP%\lit003\hipporag2.txt` и укажи в отчёте);
   - затравки задаются словарём «узел → вес»;
   - опционально — снижение веса сущностей-хабов (как idf у нас);
   - результат — фрагменты по убыванию вероятности, без затравочных.
2. **Проверка на известном первом фрагменте** — тот же протокол, что
   `second_hop_ranks` (пары многошаговых вопросов): затравка — первый
   фрагмент. Сравнить с нынешним обходом при текущих настройках
   (`hop_decay=0.5`, idf выключен): MRR, hit@8/16/30, медиана,
   недостижимые. Перебрать `alpha` ∈ {0.3, 0.5, 0.7, 0.85} и вес рёбер
   между сущностями ∈ {0, 0.5, 1}.
3. **Проверка на уровне вопроса** по слепку
   `capture/session-0819/trace-always.jsonl`:
   - затравки HippoRAG-стиля: фрагменты канала `base` (первые k по
     рангу, вес — балл) **плюс** сущности, чьё название встречается
     в тексте вопроса (лемматизация — чем уже пользуется проект; если
     её нет — нормализация регистра и точное вхождение);
   - PPR → 30 фрагментов (как нынешний графовый канал);
   - сравнить с каналом `graph` из слепка: доля эталонных фрагментов
     в 30; **эталонные фрагменты, которых нет в `base`** («только из
     графа») — сколько находит каждый вариант; разбивка по
     `question_type`;
   - парный бутстрап по вопросам для разницы (в проекте есть функции
     бутстрапа — найди и используй).
4. Скрипт запуска `scripts/ppr_offline.py`, результаты —
   `artifacts/metrics/ppr_offline.json` не писать (эта папка запрещена),
   а в `%TEMP%\ppr_offline.json` и таблицей в отчёт.
5. Тесты `tests/test_graph_ppr.py` на маленьком искусственном графе:
   сумма вероятностей ≈ 1, затравочный узел не возвращается,
   достижимость, влияние `alpha`, сходимость.

## Критерии

- **Отбросить PPR**, если на уровне вопроса лучший вариант находит
  «только из графа» эталонных фрагментов не больше нынешнего канала
  **и** проигрывает по доле эталонных в 30.
- Иначе — кандидат на серверную проверку в спринте 2.
- Код: тесты проходят, ruff чистый, существующие тесты графа не падают.

## Примечания

- В рабочей копии папки `artifacts` нет (она вне git). Кэш и разбор
  лежат в основном репозитории — указывай их переменными окружения,
  **только чтение**:
  `$env:CACHE_DIR='C:\python\rag_textbook\artifacts\cache'`,
  `$env:PARSED_DIR='C:\python\rag_textbook\artifacts\parsed'`,
  `$env:RAG_ENV_FILE='tests-no-such-env-file'`. Писать в основной
  репозиторий нельзя (песочница и так не даст). Если SQLite не
  открывается на чтение (режим WAL требует записи рядом с файлом),
  скопируй базы в `%TEMP%\cache011\` и укажи `CACHE_DIR` туда.
- Кэш извлечения: `artifacts/cache/extraction.sqlite3` (только чтение).
  Есть ещё `artifacts/cache/embeddings.sqlite3` — если там есть векторы
  вопросов и фрагментов, можно добавить вариант затравок по близости,
  но это необязательно.
- Сети не нужно. Правила экономии контекста — в AGENTS.md.
