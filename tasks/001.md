# Задача 001: `inspect_cell.py` должен не только печатать, но и браковать

## Зачем

`scripts/inspect_cell.py` показывает сводку по файлу ячейки замера, но
ничего не проверяет: код возврата всегда 0. Скрипты замеров не могут на нём
остановиться, а негодный файл (пустые ответы, мало вопросов, битый JSON)
замечается только глазами.

## Что сделать

1. Вынести логику в функцию `inspect(path: Path, *, expected: int | None,
   max_empty_share: float) -> list[str]`, возвращающую список проблем
   (пустой список — файл годен). Печать сводки оставить как есть.
2. `main(argv: list[str] | None = None) -> int` с аргументами:
   - файлы (один и более);
   - `--expected N` — сколько ответов должно быть (по умолчанию не проверять);
   - `--max-empty-share X` — допустимая доля пустых ответов, по умолчанию 0.05.
3. Проблемы, которые надо ловить:
   - файл не читается или не JSON — проблема, а не падение скрипта;
   - нет ни одного ответа;
   - число ответов не равно `--expected`, если он задан;
   - доля пустых ответов больше `--max-empty-share`;
   - в метаданных нет модели ответа (`summary["чем сделано"]["модель ответа"]`).
4. Для каждого негодного файла печатать строку `   НЕГОДЕН: <проблемы через "; ">`.
   Код возврата 1, если негоден хотя бы один файл, иначе 0.
5. Тесты в `tests/test_inspect_cell.py` на каждую проблему из п. 3 и на
   годный файл. Файлы создавать во временной папке (`tmp_path`),
   без внешних сервисов. Импорт скрипта — через `importlib` по пути.

## Можно менять

- `scripts/inspect_cell.py`
- `tests/test_inspect_cell.py` (новый)
- `tasks/001-report.md` (новый, отчёт)

## Критерий приёмки

- новые тесты проходят, существующие не затронуты;
- на годном файле вывод сводки прежний, код возврата 0;
- все пять проблем ловятся и дают код 1.
