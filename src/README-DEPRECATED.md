# Каталог `src/` — прежняя реализация, выведена из эксплуатации

Код в этом каталоге **больше не используется**. Рабочая версия — пакет
[`rag_textbook/`](../rag_textbook) в корне репозитория.

Каталог сохранён временно, по двум причинам:

1. `deepeval_eval.py` содержит генеративные метрики (Answer Relevancy, Faithfulness),
   которые ещё не перенесены: новый харнесс закрывает метрики **поиска**,
   а генеративные останутся отдельной задачей.
2. `backfill_graph_from_chroma.py` документирует, как именно проводились
   прошлые графовые прогоны — это нужно для сопоставления старых и новых метрик.

## Почему код заменён, а не поправлен

Основные дефекты были архитектурными, а не точечными:

| Модуль | Проблема |
|---|---|
| `chunker.py` | `_block_to_text` возвращал описание от модели зрения **вместо** исходного блока, поэтому LaTeX формул и HTML таблиц в индекс не попадали |
| `settings.py` | значения читались один раз при импорте; пустая переменная означала «включено»; пароль хранился обычной строкой |
| `vectorstore.py` | Chroma поверх SQLite, метрика L2 по ненормированным векторам, обработчик `disk I/O error` как симптом конкурентного доступа |
| `retriever.py` | BM25 строился в оперативной памяти из всего корпуса при каждом создании цепочки; графовый обход `*1..2` по 280k рёбер co-occurrence |
| `llm.py` | ~300 строк поверх устаревшего `langchain_community.ChatOllama` с сырыми `requests` |
| `rag_chain.py` | отсутствовал history-aware retriever: диалоговый режим искал по тексту последней реплики |
| `neo4j_client.py` | `UNWIND` на сотни тысяч строк одной транзакцией; сущности как сырые токены; клики co-occurrence |

Полный перечень с решениями — в [`docs/MIGRATION-PLAN.md`](../docs/MIGRATION-PLAN.md).

## Что делать дальше

После переноса генеративных метрик каталог удаляется целиком.
Новые изменения сюда вносить не нужно.
